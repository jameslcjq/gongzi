# 待实现计划：一体化自动切换 Key 登录

## 1. 当前结论

自动切换 Key 登录暂不接入正式业务流程。

已验证的问题：

1. 一体化登录 Key / 证书选择窗口是 Windows 原生窗口，不是网页 DOM 弹窗。
2. 设置弹窗打开后，一体化 webview 会处于背景层。此时原生窗口自动化可能受前台窗口、焦点、置顶层级和确认按钮状态影响。
3. 登录页采集能看到证书认证请求，但网页侧没有稳定暴露“选择 Key + 输入 PIN + 确定”的完整 DOM 事件。
4. 当前自动化助手可以采集 Key 窗口、候选项，并尝试选择/确认，但还不能保证在所有机器、所有 Key 驱动和所有前后台状态下稳定成功。
5. 因此，自动切 Key 登录不应嵌入“系统设置 -> 自动填入预算项目编码”等普通业务按钮里，避免用户以为只是读取编码，实际触发原生登录自动化。

## 2. 当前已保留的能力

保留：

- 采集助手入口。
- 登录 Key 弹窗采集。
- 候选 Key 列表读取。
- 调试工具中的手动测试选择 Key 能力。

移除 / 不接入：

- “自动填入预算项目编码”中自动选择 0101 Key、输入 PIN、点击确定。
- 自动填入前强制切换到“中科单位核算”的 90 秒等待。
- 业务流程中默认自动登录或自动切换 0101 / 0201 Key。

## 3. 用户侧当前使用方式

当前稳定用法：

1. 用户先在“一体化系统”页签中手动登录 0101 业务操作账号。
2. 打开系统设置。
3. 在“单位信息”中点击预算项目编码的“自动填入”。
4. 程序直接读取一体化基础资料接口，自动填入：
   - “事业人员工资”对应的在职预算项目编码。
   - “退休提租补贴 / 退休人员提租补贴”对应的退休预算项目编码。

如果没有登录 0101，应提示用户先登录，而不是自动弹 Key 窗口。

## 4. 后续稳定实现目标

后续如果继续做自动切 Key 登录，目标不是简单“能点一次”，而是形成可恢复、可观测、可停止的登录编排。

目标能力：

1. 打开专用 0101 登录页签，使用独立 partition，不污染 0201 审核页。
2. 只在用户明确点击“自动登录 0101”或自动化流水线明确要求登录时触发。
3. 前台化一体化窗口和 Key 原生窗口，保证 Key 窗口可见且在最前。
4. 自动匹配单位编码 + Key 后缀：
   - 业务操作 Key：`019052-0101` 这类后缀。
   - 审核 Key：`019052-0201` 这类后缀。
5. 支持 PIN 输入，但 PIN 不写死、不长期保存；需要后续决定是否允许本机加密保存。
6. 登录后必须校验当前账号：
   - `ukey` 包含目标单位编码和目标 Key 后缀。
   - 0101 只用于业务操作、推送、录入、送审前置操作。
   - 0201 只在后续审核自动化明确需要时才打开。
7. 自动化失败时必须返回清楚原因，并停在可人工接手的状态。

## 5. 建议实现方式

### 5.1 页面层

新增独立入口，不挂在普通设置项上：

- “一体化系统”工具栏：`自动登录 0101`
- “一体化系统”工具栏：`自动登录 0201`
- 或调试工具页内：`测试自动登录 0101 / 0201`

入口必须清楚提示会操作 Windows 原生 Key 窗口。

### 5.2 编排层

新增 `IntegrationLoginOrchestrator`，负责串联：

1. 打开目标页签。
2. 等待进入 `/portal/login` 或 `/idp/authcenter/ActionAuthChain`。
3. 激活宿主窗口。
4. 调用 `laojiu-automation-helper.exe select-key`。
5. 等待网页登录完成。
6. 调用一体化用户信息接口校验 `loginId / ukey / orgCode / orgName`。
7. 输出结构化结果和日志。

### 5.3 原生助手层

`laojiu-automation-helper.exe` 后续需要增强：

1. 支持按窗口句柄或进程更精准定位当前登录窗口。
2. 支持把 Key 窗口置前。
3. 支持选择后等待下拉值真正变化。
4. 支持确定按钮可用性检测。
5. 支持失败截图和控件树保存。
6. 支持返回 `selectedText / confirmed / pinFilled / beforeCurrentKey / afterCurrentKey`。

## 6. 停止条件

自动登录流程必须在以下情况立即停止：

1. 找不到 Key 窗口。
2. 找到多个无法唯一判断的 Key。
3. 候选 Key 中没有目标单位编码或目标后缀。
4. PIN 输入框不可用。
5. 确定按钮不可用或点击后未登录。
6. 登录后账号不是目标单位或目标 Key 角色。
7. 当前有 0201 审核页正在执行业务，不能抢焦点或复用会话。

## 7. 验收标准

第一阶段验收：

- 手动打开登录页后，点击“测试自动登录 0101”，能稳定选中 `单位编码-0101`，输入 PIN，并登录成功。
- 登录成功后能显示当前 `loginId / ukey / orgName`。
- 失败时有明确错误和诊断包。

第二阶段验收：

- 0101 和 0201 使用不同独立页签和不同 partition。
- 自动化流程能在需要 0101 时确认已是 0101；不是则停止并提示。
- 不再依赖设置弹窗背景页触发原生窗口自动化。

第三阶段验收：

- 自动推送、自动录入、自动送审流水线可在“已登录 0101”的前提下运行。
- 审核 Key 自动化只在后续明确实现审核接力时加入，不在启动时提前打开。

## 8. 当前代码边界

截至本计划保存时：

- “自动填入预算项目编码”只负责读取已登录 0101 的预算项目基础资料。
- 自动切 Key 登录不在该按钮中执行。
- 调试工具仍可用于采集和测试 Key 窗口，为后续开发提供证据。
