# 月度工资报账迁移设计

目标：脱离 `工资报账.xlsx` 模板和 VBS 脚本，把每月工资报账变成系统内可追溯、可校验、可导出的业务流程。

## 数据来源

月度工资报账使用五类来源：

| 来源 | 用途 |
|---|---|
| 本月工资表 / 公办在职 | 与一体化在职全量比对；提供在职工资、扣款、实发等字段 |
| 本月工资表 / 遗补或遗属补助 | 与一体化其他全量比对；提供遗属补助人数和金额 |
| 一体化退休 | 提供退休人员房补数据 |
| 社保费未申报汇总信息.xls | 按征收品目汇总应补（退）费额 |
| 税款计算_工资薪金所得.xls | 汇总个税总额，并按人生成负数补发工资 |

## 月度核对

工资表导入后，先做三张一体化表的月度核对：

| 工资表来源 | 系统表 | 核对范围 |
|---|---|---|
| 公办在职 | 一体化在职 | 人员、身份证、姓名、账号、人数、工资列、扣款列、实发列 |
| 遗补 / 遗属补助 | 一体化其他 | 人员、身份证、姓名、账号、人数、遗属补助、补发、合计 |
| 退休房补数据 | 一体化退休 | 人员、身份证、姓名、账号、退休房补金额 |

核对结果分为：

- 新增人员
- 减少人员
- 字段变化人员
- 无变化人员

第一版先实现解析和预处理；后续再接入页面确认后写回三张一体化表。

## 社保汇总规则

社保文件以 `征收品目` 为分类键，汇总 `应补（退）费额(元)`。

系统内部保存为：

```text
征收品目 -> 金额合计
```

后续报表读取这些分类金额生成五险一金、报销凭证、凭证和保险导入。分类名称不直接写死在公式里，后续应建立“征收品目映射表”，把税务导出名称映射到系统口径：

- 养老保险个人
- 养老保险单位
- 职业年金个人
- 职业年金单位
- 医疗保险个人
- 医疗保险单位
- 失业保险个人
- 失业保险单位
- 工伤保险
- 公积金个人
- 公积金单位

## 个税与补发工资

个税文件有两类用途：

1. 报账汇总读取个税总金额。
2. 按身份证匹配一体化在职，生成每个人的负数补发工资。

规则：

```text
补发工资 = - 个税金额
```

异常处理：

- 身份证匹配成功：允许自动生成扣税补发工资。
- 身份证不匹配但姓名匹配：进入异常报告，需人工确认。
- 身份证和姓名都找不到：进入异常报告，需人工确认。

## 报表输出

最终报表不再依赖 `工资报账.xlsx` 的公式，而是由系统读取结构化数据生成：

- 五险一金
- 自动生成
- 工退遗汇总
- 报销凭证
- 保险导入
- 补发工资
- 个税异常报告

打印范围：

- 工资表
- 遗补表
- 退休房补表
- 五险一金
- 自动生成
- 工退遗汇总
- 报销凭证

## 落地顺序

1. 后端预处理：解析工资表、社保表、个税表。
2. 月度核对：把工资表数据与一体化在职、一体化其他、一体化退休做全字段差异。
3. 人工确认：页面展示新增、减少、变化，并允许写回一体化表。
4. 报账计算：把旧模板中 `工资`、`社保`、`凭证`、`自动生成`、`五险一金`、`导入用` 的公式转成系统规则。
5. 对账验算：同一批数据同时跑旧模板和新系统，金额对平后停止依赖旧模板。
