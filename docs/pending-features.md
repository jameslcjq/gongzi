## 自定义字段（增删字段）

来源：2026-05-01 讨论。

### 需求

每张工作表都允许使用者自行添加/删除字段，应对实际业务里临时新增的工资项、津贴项等。

### 可行方案

- 用户的自定义字段存到独立的 `worksheet_custom_fields` 表（per-install 覆盖），不修改 `docs/data/worksheets-retained.json`（那是基线结构）
- 启动时合并：基线字段 + 用户自定义字段，调用现有的 `syncWorksheetColumns` 走 `ALTER TABLE ADD COLUMN`
- 删除走 `ALTER TABLE DROP COLUMN`（SQLite 3.35+ 原生支持）

### 待决策

1. **操作范围**：只允许"加"？还是"加 + 删 + 改名 + 改类型"都开放
2. **作用域**：所有 20 张表都允许，还是只放开纯本地表（人事系列、对照表等），锁住"导入文件驱动"的表（一体化在职、预算在职、其他人员等）
3. **字段位置**：新字段固定追加在末尾，还是允许插到任意位置（SQLite 重排列序成本高）
4. **可选类型**：文本 / 数值 / 日期 / 单选 / 多选 / 证件 — 给几种；选项类是否要带下拉值列表
5. **冲突处理**：
   - 给"导入驱动"的表加字段后，下次导入的 xls 缺这一列 → 严格签名校验会失败。要不要对自定义字段豁免签名校验？
   - 工作流（如 `更新薪级`、`计算基础性绩效工资`、`调整乡镇补贴`）依赖具体字段名（薪级、薪级工资*、岗位津贴、生活补贴、乡镇工作年限（年）、新补贴标准（元/月） 等），用户删除/改名会让规则跑挂
6. **删除策略**：硬删除（DROP COLUMN，数据丢）还是软删除（仅元数据隐藏，DB 列保留）
7. **被规则引用的字段是否锁死**：UI 禁止删/改名

### 最保守的第一版（备选）

- 只允许"加"、末尾追加、类型只有 文本 / 数值 / 日期 三种
- 自定义字段不计入导入签名校验（允许 xls 里没有这一列）
- 删除/改名做"软删除/重命名"（仅元数据层，DB 列保留）
- 工作流引用的字段在 UI 上禁动

### 影响范围

- `docs/data/worksheets-retained.json`（基线，不改）
- 新增 `worksheet_custom_fields` 表（custom 字段元数据持久化）
- `app/src/main/db/connection.ts` 的 `syncWorksheetColumns` 需读取自定义字段
- `app/src/main/db/metadata.ts` / 渲染端组件需要把基线 + 自定义合并
- `app/src/main/services/worksheetInference.ts` 的 `matchesSignature` 要把自定义字段排除（如果决定豁免签名校验）
- `WorksheetView.vue` / `RecordFormDialog.vue` 已经是按字段元数据渲染，无需大改
- 新增管理界面：字段管理 dialog（每张表的"..."菜单进入）
